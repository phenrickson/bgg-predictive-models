## What this redesign is for

The bgg-rating-models training pipeline (hurdle, complexity, rating, users_rated, geek_rating) was rewritten to support honest year-over-year evaluation. Core ideas:

- A **snapshot** is the feature universe frozen at a point in time. Built once from BigQuery, then everything trains offline against that frozen parquet.
- **Splits** slice the snapshot by year into train/tune/test. Each split is named (`standard`, `yoy_2018`, ..., `yoy_2024`).
- **Experiments** train one candidate against one or more splits inside one snapshot, producing per-split results that are by-construction comparable.
- **Simulations** evaluate the full chain (complexity → rating + users_rated → geek_rating) on the year *after* a split's test fold (`test_through + 1`). This is the system-level metric that judges the methodology, not the per-model metrics.

Tree layout:

```
models/bgg/snapshots/v1/
  universe.parquet
  metadata.json
  splits/{standard, yoy_2018, ..., yoy_2024}/
    train.parquet, tune.parquet, test.parquet, metadata.json
  experiments/{model_type}/{candidate}/v{N}/
    config.json, registration.json, finalized.pkl, summary.json
    results/{split_name}/
      pipeline.pkl, metrics.json, parameters.json, feature_importance.csv
      predictions/{tune.parquet, test.parquet, score.parquet}
      plots/diagnostics.png
  simulations/{name}/{split_name}/v{N}/
    registration.json, metrics.json, predictions.parquet, top_100_games.png
```

## What's done

### Stage 1: Snapshot + split storage (Tasks 1–10)

- `src/models/snapshot_storage.py` — `SnapshotStorage` class. Owns paths and IO for the whole tree. Methods for universe, splits, candidate-level artifacts (config/registration/finalized), per-result artifacts, simulation artifacts.
- `src/models/build_snapshot.py` — CLI. `bgg-build` runs this. Pulls features (BQ via `BGGDataLoader`) into `universe.parquet`.
- `src/models/build_split.py` — CLI. Single split mode + `--yoy` mode that creates a family of `yoy_{year}` splits.
- All hermetic-tested in `tests/test_snapshot_storage.py`, `tests/test_build_snapshot.py`, `tests/test_build_split.py` (using `tmp_path`).

### Stage 2: Candidate config resolution (Tasks 11–12)

- `config.yaml` got `candidates:` lists under each `models.{type}` block. Each candidate is a free-form dict (algorithm, preprocessor_kwargs, upstream, min_ratings/min_weights, etc).
- `src/models/candidate_config.py` — `find_candidate(model_type, name)` and `list_candidates(model_type)`, reading raw YAML.

### Stage 3: Pure-function refactor + orchestration (Tasks 13–17)

- `src/models/outcomes/train.py` reduced to **`train_one(model_type, candidate_config, train_df, tune_df, test_df, ...)`** — pure data-frame in, artifacts dict out (`pipeline`, `metrics`, `parameters`, `tune_predictions`, `test_predictions`, `feature_importance`, optionally `optimal_threshold`). No CLI, no IO.
- `src/pipeline/train.py` — snapshot-aware orchestrator. Loads frames from `SnapshotStorage`, joins upstream `score.parquet` columns, calls `train_one` per split, writes `save_result(...)` and `summary.json`. Diagnostic plot saved per result.
- `src/pipeline/score.py` — scores trained pipeline on the universe; writes `score.parquet` per (candidate, split). Used between cascade layers (complexity scores feed rating/users_rated).
- Justfile recipes — see "Justfile reference" below.

### Stage 4 (renamed Stage 5): Finalize (Task 22)

- `src/pipeline/finalize.py` — refits pipeline on snapshot universe filtered through `finalize_through`. Auto-loads upstream from `registration.json` so cascaded models get their upstream score columns at refit time.
- Finalize is a **deployment artifact**, NOT used by simulation. Skipped during evaluation runs.

### Stage 5.5: Simulation (Task 22.5)

- `src/pipeline/evaluate_simulation.py` — loads **per-split `pipeline.pkl`** (NOT `finalized.pkl`), runs `simulate_batch` from `src/models/outcomes/simulation.py` on the year following the split's test fold (`test_through + 1`), writes per-game predictions + system-level metrics.
- Auto-emits `top_100_games.png` forest plot via `src/pipeline/plot_simulation.py`.

### Stage 6: K-fold OOF (Tasks 19–20)

- `src/models/oof.py` — `kfold_oof_predict` utility.
- `src/pipeline/score.py` for upstream models (complexity/rating/users_rated): the `score.parquet` train-row predictions come from K-fold OOF instead of in-sample. Configurable via candidate's `oof_folds` (default 5).
- Downstream models train on honest features.

### Bug fixes during the session

- **`ComplexityModel.prepare_features` filter** (`num_weights >= min_weights`). Was a BQ-load filter (`data_config.min_weights`) in the legacy code that the snapshot path silently dropped. Caused complexity to train on ~104k rows including unrated games.
- **`RatingModel.prepare_features` filter** (`users_rated >= min_ratings`). Same bug shape as complexity.
- **0=NA semantics**: complexity, rating, geek_rating actuals of `0` mean "no votes" / "NA". The above `prepare_features` filters cover complexity/rating. `users_rated == 0` is a real value (kept). hurdle 0 is a real label (kept). geek_rating's existing `prepare_features` already filters/handles 0s during train and replaces with prior 5.5 during tune/test (legacy convention; left as-is).
- **`pipeline.finalize` upstream auto-resolve**: reads `upstream_experiments` from each candidate's `registration.json` so `bgg-finalize-all` doesn't need explicit `--upstream` flags.
- **`finalize_through` default**: justfile defaults from `config.yaml`'s `years.training.test_through` (currently 2024).
- **Path rename**: `models/experiments/_snapshots/` → `models/bgg/snapshots/` to disambiguate the inner `experiments/` directory.

### Logging additions to `train_one`

Per training run logs (visible during `bgg-train-all`):

- Model + algorithm name
- Split year ranges (train ≤ X, tune Y..Y, test Z..Z)
- Upstream cascade dict
- Input frame shapes before/after `prepare_features`
- Per-fold target stats: regression (min/max/mean/std/n_zero), classification (pos/neg counts + pos_ratio)
- Tuning metric, patience, sample-weights config
- Best params after tune
- One-line metric summary per fold
- Optimal threshold (classification)
- Top-10 features by abs(coefficient) or importance

The `bgg-*` recipes (verify form before invoking):

- `bgg-build` — build a snapshot from BQ
- `bgg-split snapshot split` — build one named split
- `bgg-yoy snapshot start end` — build the YoY family
- `bgg-train snapshot model candidate splits upstream` — train one candidate
- `bgg-score snapshot model candidate splits upstream` — score one candidate
- `bgg-train-all snapshot splits` — full chain (hurdle → complexity train+score → rating + users_rated train+score → geek_rating). `splits=all` resolves to every split in the snapshot.
- `bgg-finalize snapshot model candidate finalize_through` — refit one candidate
- `bgg-finalize-all snapshot finalize_through` — finalize the chain. Defaults `finalize_through` from config.
- `bgg-simulate snapshot split name samples` — simulate one split
- `bgg-simulate-all snapshot splits name samples` — simulate every (or named) splits. `splits=all` default.
- `bgg-plot snapshot split name top version` — re-render the forest plot for an existing simulation
